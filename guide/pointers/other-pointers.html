Другие виды указателей

TODO: расписать по отдельным подглавам

Продолжаем изучение Go! В предыдущих ответах мы рассмотрели базовые указатели, указатели на слайсы, мапы, в структурах, встроенные структуры с указателями и их связь с интерфейсами. Go имеет простой дизайн указателей (все они типа *T, где T — любой тип), без "умных" указателей как в C++ (из-за garbage collector). Но есть несколько аспектов, которые мы не затронули:

  • Указатели на функции (function pointers): Полезны для callback'ов или динамического вызова функций.
  • Указатели на chan (channels): Редко используются, но позволяют модифицировать канал.
  • Указатели на интерфейсы: Для хранения ссылок на интерфейсные значения.
  • Многоуровневые указатели (pointer to pointer, **T): Для более сложных сценариев, как изменение указателя.
  • Unsafe указатели (из пакета unsafe): Advanced и опасные, для низкоуровневого доступа (избегай как новичок).

Я объясню каждый с примерами, начиная с простых. Код можно скопировать и запустить.

2. Указатели на chan (channels)

Channels — это встроенные типы для goroutines. Они уже reference types (как слайсы), так что указатели на chan (*chan T) редки. Но они позволяют сделать канал nil или перезаписать внутри функции.

package main

import "fmt"

func modifyChan(ch *chan int) {
    // Отправляем значение
    *ch <- 42
    
    // Закрываем канал
    close(*ch)
    
    // Делаем nil
    *ch = nil
}

func main() {
    ch := make(chan int)
    
    go func() {
        modifyChan(&ch)
    }()
    
    // Получаем
    val, ok := <-ch
    fmt.Println("Значение:", val, "OK:", ok)  // 42 true
    
    // После nil
    if ch == nil {
        fmt.Println("Канал стал nil")
    }
}
  • Что происходит? Указатель позволяет модифицировать сам канал (close, nil). Без указателя изменения внутри функции (как append для слайсов) не повлияют на оригинал.
  • Зачем? В сложных concurrency сценариях, где канал нужно динамически менять (редко). Обычно достаточно простых chan.

3. Указатели на интерфейсы

Интерфейсы сами по себе могут хранить указатели (как мы обсуждали), но указатель на интерфейс (*Interface) — это указатель на переменную интерфейсного типа. Редко используется, но полезно для изменения интерфейсного значения.

package main

import "fmt"

type Describer interface {
    Describe() string
}

type Cat struct {}
func (c Cat) Describe() string { return "Meow" }

type Dog struct {}
func (d Dog) Describe() string { return "Woof" }

func changeDescriber(d **Describer) {
    var newD Describer = Dog{}
    *d = &newD  // Меняем интерфейс на другой
}

func main() {
    var animal Describer = Cat{}
    var ptr *Describer = &animal
    
    fmt.Println((*ptr).Describe())  // Meow
    
    changeDescriber(&ptr)
    fmt.Println((*ptr).Describe())  // Woof
}
  • Что происходит? *Describer — указатель на интерфейс. Мы меняем, что хранит интерфейс (с Cat на Dog).
  • Зачем? В advanced случаях, как dependency injection или mocking в тестах, где нужно динамически менять имплементацию интерфейса.

4. Многоуровневые указатели (pointer to pointer, **T)

Это указатель на указатель (**int). Полезно, когда нужно изменить сам указатель (например, в функциях, возвращающих указатели).

package main

import "fmt"

func allocate(ptr **int) {
    var val int = 42
    *ptr = &val  // Меняем указатель на новый адрес
}

func main() {
    var p *int  // nil
    
    allocate(&p)  // Передаём pointer to pointer
    fmt.Println(*p)  // 42
    
    // Меняем значение
    **(&p) = 100  // Двойное dereference
    fmt.Println(*p)  // 100
}
  • Что происходит? **int позволяет изменить, куда указывает первый указатель. Это как в C для динамической аллокации.
  • Зачем? В функциях вроде scanf в C (изменение переменной по ссылке). В Go редко, т.к. есть return values, но полезно для C-interop или сложных структур.

5. Unsafe указатели (пакет unsafe)

Пакет unsafe предоставляет unsafe.Pointer — универсальный указатель, как void* в C. Он обходит type safety Go для низкоуровневого кода (CGO, memory hacks). Опасно для новичков! Может вызвать краши, утечки или undefined behavior. Избегай, пока не поймёшь.

package main

import (
    "fmt"
    "unsafe"
)

func main() {
    var x int = 42
    p := unsafe.Pointer(&x)  // Конвертируем в unsafe.Pointer
    
    // Конвертируем обратно
    pp := (*int)(p)
    fmt.Println(*pp)  // 42
    
    // Меняем как uintptr (адрес как число)
    up := uintptr(p)
    fmt.Println(up)  // Адрес в hex
    
    // Опасно: Арифметика (не рекомендуется)
    up += unsafe.Sizeof(int(0))  // Сдвиг на размер int
    // Теперь up — invalid, не используй!
}
  • Что происходит? unsafe.Pointer позволяет кастовать типы, делать арифметику адресов. Но Go не гарантирует безопасность.
  • Зачем? Для интеграции с C, оптимизаций или хаков (например, в reflect или syscall). Не используй в обычном коде — лучше стандартные указатели.

Заключение и советы

Это основные "виды" или аспекты указателей, которые мы не разбирали. В Go указатели простые, и большинство кода обходится без них (кроме pointer receivers в методах). Если нужно, начни с указателей на функции — они полезны для callbacks.

  • Когда использовать: Только если стандартные способы (return, value) не подходят.
  • Ошибки: Nil dereference — всегда проверяй. Для unsafe — читай документацию и будь осторожен.
  • Практика: Напиши callback с указателем на функцию для калькулятора.
