Указатели на слайсы

Определение

Слайсы (slices) в Go — это динамические массивы, которые уже являются ссылочными типами (reference types).

Это значит, что когда ты передаёшь слайс в функцию, он передаётся по ссылке (не копируется весь массив), и изменения внутри функции повлияют на оригинал.

Слайс внутри себя содержит указатель на underlying array, длину и capacity.

Однако иногда возникает необходимость в указателях на слайсы (*[]T). Это не очень распространено, потому что слайсы уже "ссылочные", но указатели на них полезны в определённых случаях:

  • Для модификации самого слайса: Например, чтобы изменить его размер, capacity или сделать nil внутри функции.
  • Для опциональных слайсов: Указатель может быть nil, что означает "нет слайса", в отличие от пустого слайса ([]int{}), который не nil.
  • В структурах: Чтобы избежать копирования слайса при присваивании структур (хотя слайсы копируются дешево, так как это всего 24 байта: указатель + len + cap).
  • Когда нужно явно контролировать ссылку: Например, в сложных структурах данных или для избежания неожиданного поведения.

Важно

Указатели на слайсы редки в повседневном коде Go. Чаще всего достаточно просто слайсов.

Давай разберём примеры, чтобы понять.

Пример 1: Базовое объявление и использование указателя на слайс

Здесь мы создаём указатель на слайс и меняем его через dereferencing.

package main

import "fmt"

func main() {
    // Создаём слайс
    numbers := []int{1, 2, 3}
    
    // Указатель на слайс
    var ptr *[]int = &numbers
    
    fmt.Println("Оригинальный слайс:", numbers)  // [1 2 3]
    
    // Меняем элемент через указатель (dereferencing)
    (*ptr)[1] = 99
    fmt.Println("После изменения элемента:", numbers)  // [1 99 3]
    
    // Добавляем элемент через append (нужно dereference)
    *ptr = append(*ptr, 4)
    fmt.Println("После append:", numbers)  // [1 99 3 4]
    
    // Делаем слайс nil через указатель
    *ptr = nil
    fmt.Println("После nil:", numbers)  // [] (но это пустой слайс, т.к. numbers теперь nil)
}
  • Что происходит? *ptr даёт доступ к самому слайсу. Мы можем менять элементы, добавлять через append или устанавливать в nil. Без указателя мы бы работали напрямую, но указатель позволяет "ссылаться" на слайс как на переменную.

Пример 2: Передача указателя на слайс в функцию

Слайсы передаются по ссылке, но если функция должна изменить сам слайс (например, перезаписать его или сделать nil), нужен указатель.

Без указателя (стандартный случай — работает для изменений внутри):

package main

import "fmt"

func modifySlice(s []int) {
    s[0] = 100  // Изменит оригинал
    s = append(s, 4)  // Это НЕ изменит оригинал! (s — локальная копия ссылки)
}

func main() {
    numbers := []int{1, 2, 3}
    modifySlice(numbers)
    fmt.Println(numbers)  // [100 2 3] (append не сработал на оригинале)
}
  • Почему append не изменил? s в функции — копия слайса (указатель + len + cap). Append создаёт новый слайс и присваивает локальной s, но оригинал не меняется.

С указателем:

package main

import "fmt"

func modifySlicePtr(s *[]int) {
    (*s)[0] = 100  // Изменит оригинал
    *s = append(*s, 4)  // Теперь изменит оригинал!
    *s = nil  // Можно сделать nil
}

func main() {
    numbers := []int{1, 2, 3}
    modifySlicePtr(&numbers)
    fmt.Println(numbers)  // [] (стал nil после изменений)
}
  • Зачем? Полезно, если функция должна полностью перезаписать слайс (например, в парсере, где слайс может стать nil при ошибке).

Пример 3: Указатель на слайс в структуре

Это полезно, чтобы структура могла иметь "опциональный" слайс (nil) или чтобы избежать копирования при присваивании.

package main

import "fmt"

type Data struct {
    Items *[]string  // Указатель на слайс строк
}

func main() {
    d := Data{}
    fmt.Println("Изначально:", d.Items)  // <nil> (нет слайса)
    
    // Инициализируем
    items := []string{"apple", "banana"}
    d.Items = &items
    
    // Меняем через указатель
    (*d.Items)[0] = "orange"
    fmt.Println("После изменения:", items)  // [orange banana]
    
    // Добавляем
    *d.Items = append(*d.Items, "cherry")
    fmt.Println("После append:", items)  // [orange banana cherry]
    
    // Проверяем на nil
    if d.Items == nil {
        fmt.Println("Нет данных")
    } else {
        fmt.Println("Есть данные:", *d.Items)
    }
}
  • Зачем? В структурах слайсы без указателя всегда "существуют" (даже пустые). С указателем можно отличить "пустой" от "отсутствующий". Полезно в JSON (marshal/unmarshal) или базах данных.

Пример 4: Nil-указатель на слайс и проверка

package main

import "fmt"

func processSlice(ptr *[]int) {
    if ptr == nil {
        fmt.Println("Указатель nil — нет слайса")
        return
    }
    if len(*ptr) == 0 {
        fmt.Println("Слайс пустой, но не nil")
        return
    }
    fmt.Println("Слайс:", *ptr)
}

func main() {
    var nilPtr *[]int  // nil
    processSlice(nilPtr)  // "Указатель nil — нет слайса"
    
    emptySlice := []int{}  // Пустой слайс (не nil)
    processSlice(&emptySlice)  // "Слайс пустой, но не nil"
    
    fullSlice := []int{1, 2}
    processSlice(&fullSlice)  // "Слайс: [1 2]"
}
  • Разница: Пустой слайс ([]int{}) != nil. Nil-указатель полезен для ошибок или отсутствия данных.

Советы по использованию

  • Когда избегать: Если достаточно стандартного поведения слайсов (изменение элементов, но не перезапись) — не используй указатели. Они добавляют сложность.
  • Ошибки: Всегда проверяй на nil перед dereferencing (if ptr != nil), иначе panic.
  • Производительность: Указатели на слайсы — это extra уровень индирекции, но в Go это дешево.
  • Практика: Попробуй написать функцию, которая принимает *[]int и сортирует слайс на месте (используй sort.Ints(*s)).
