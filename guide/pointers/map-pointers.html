Указатели на мапы

Определение

Мапы (maps) в Go — это ассоциативные массивы (ключ-значение), и они, как и слайсы, являются ссылочными типами (reference types).

Это значит, что когда ты передаёшь мапу в функцию, она передаётся по ссылке (не копируется вся мапа), и изменения внутри функции (добавление/удаление элементов) повлияют на оригинал.

Мапа внутри содержит указатель на underlying data structure.

Однако указатели на мапы (*map[K]V) используются реже, чем на слайсы, потому что мапы уже "ссылочные". Но они полезны в похожих случаях:

  • Для модификации самой мапы: Например, чтобы сделать мапу nil, перезаписать её или инициализировать внутри функции.
  • Для опциональных мап: Указатель может быть nil, что означает "нет мапы", в отличие от пустой мапы (map[int]string{}), которая не nil.
  • В структурах: Чтобы отличить "пустую мапу" от "отсутствующей", или для JSON (где nil — null).
  • Избегание копирования: Хотя мапы копируются дешево (всего указатель), указатель добавляет explicit контроль.

Важно

Указатели на мапы не очень часты в Go-коде. Чаще всего достаточно просто мап.

Давай разберём примеры, чтобы понять.

Пример 1: Базовое объявление и использование указателя на мапу

Здесь мы создаём указатель на мапу и работаем с ней через dereferencing.

package main

import "fmt"

func main() {
    // Создаём мапу
    scores := map[string]int{"Alice": 90, "Bob": 85}
    
    // Указатель на мапу
    var ptr *map[string]int = &scores
    
    fmt.Println("Оригинальная мапа:", scores)  // map[Alice:90 Bob:85]
    
    // Меняем значение через указатель (dereferencing)
    (*ptr)["Alice"] = 95
    fmt.Println("После изменения значения:", scores)  // map[Alice:95 Bob:85]
    
    // Добавляем элемент
    (*ptr)["Charlie"] = 88
    fmt.Println("После добавления:", scores)  // map[Alice:95 Bob:85 Charlie:88]
    
    // Удаляем элемент
    delete(*ptr, "Bob")
    fmt.Println("После удаления:", scores)  // map[Alice:95 Charlie:88]
    
    // Делаем мапу nil через указатель
    *ptr = nil
    fmt.Println("После nil:", scores)  // map[] (но это nil мапа)
}

Что происходит? *ptr даёт доступ к самой мапе. Мы можем добавлять, удалять, менять элементы или устанавливать в nil. Без указателя мы бы работали напрямую.

Пример 2: Передача указателя на мапу в функцию

Мапы передаются по ссылке, но если функция должна перезаписать мапу целиком или сделать nil, нужен указатель.

Без указателя (стандартный случай — работает для изменений внутри):

package main

import "fmt"

func modifyMap(m map[string]int) {
    m["Alice"] = 100  // Изменит оригинал
    m = make(map[string]int)  // Это НЕ изменит оригинал! (m — локальная копия ссылки)
    m["New"] = 1  // Не повлияет на оригинал
}

func main() {
    scores := map[string]int{"Alice": 90}
    modifyMap(scores)
    fmt.Println(scores)  // map[Alice:100] (перезапись не сработала)
}

Почему перезапись не изменила? m в функции — копия мапы (указатель на данные). Присваивание новой мапы меняет только локальную переменную.

С указателем:

package main

import "fmt"

func modifyMapPtr(m *map[string]int) {
    (*m)["Alice"] = 100  // Изменит оригинал
    *m = make(map[string]int)  // Теперь изменит оригинал!
    (*m)["New"] = 1
    *m = nil  // Можно сделать nil
}

func main() {
    scores := map[string]int{"Alice": 90}
    modifyMapPtr(&scores)
    fmt.Println(scores)  // <nil> (стала nil после изменений)
}

Зачем? Полезно, если функция должна полностью перезаписать мапу (например, в кэше, где мапа может быть сброшена при ошибке).

Пример 3: Указатель на мапу в структуре

Это полезно для "опциональной" мапы в структурах.

package main

import "fmt"

type Config struct {
    Settings *map[string]string  // Указатель на мапу
}

func main() {
    c := Config{}
    fmt.Println("Изначально:", c.Settings)  // <nil> (нет мапы)
    
    // Инициализируем
    settings := map[string]string{"theme": "dark", "lang": "en"}
    c.Settings = &settings
    
    // Меняем через указатель
    (*c.Settings)["theme"] = "light"
    fmt.Println("После изменения:", settings)  // map[lang:en theme:light]
    
    // Добавляем
    (*c.Settings)["font"] = "arial"
    fmt.Println("После добавления:", settings)  // map[font:arial lang:en theme:light]
    
    // Проверяем на nil
    if c.Settings == nil {
        fmt.Println("Нет настроек")
    } else {
        fmt.Println("Есть настройки:", *c.Settings)
    }
}

Зачем? В структурах мапы без указателя всегда "существуют" (даже пустые). С указателем можно отличить "пустая" от "отсутствующая". Полезно в конфигах или API-ответах.

Пример 4: Nil-указатель на мапу и проверка

package main

import "fmt"

func processMap(ptr *map[int]string) {
    if ptr == nil {
        fmt.Println("Указатель nil — нет мапы")
        return
    }
    if len(*ptr) == 0 {
        fmt.Println("Мапа пустая, но не nil")
        return
    }
    fmt.Println("Мапа:", *ptr)
}

func main() {
    var nilPtr *map[int]string  // nil
    processMap(nilPtr)  // "Указатель nil — нет мапы"
    
    emptyMap := make(map[int]string)  // Пустая мапа (не nil)
    processMap(&emptyMap)  // "Мапа пустая, но не nil"
    
    fullMap := map[int]string{1: "one", 2: "two"}
    processMap(&fullMap)  // "Мапа: map[1:one 2:two]"
}

Разница: Пустая мапа (make(map[K]V)) != nil. Nil-указатель полезен для ошибок или отсутствия данных.

Советы по использованию

  • Когда избегать: Если достаточно стандартного поведения мап (изменение элементов, но не перезапись) — не используй указатели. Они добавляют сложность.
  • Ошибки: Всегда проверяй на nil перед доступом (if ptr != nil), иначе panic (нельзя читать/писать в nil-мэп).
  • Производительность: Мапы — это hash-таблицы, указатели на них дешевы.
  • Практика: Попробуй написать функцию, которая принимает *map[string]int и добавляет/удаляет элементы, проверяя на nil.
