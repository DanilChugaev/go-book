Функции

Цель урока

Научиться выносить повторяющуюся логику из main в именованные функции, передавать им данные и получать один или несколько результатов.

В Task Manager API функции помогут отделить проверку задачи и получение текста приоритета от запуска программы. Позже этот подход позволит построить понятную структуру приложения.

Зачем нужны функции

Функция — именованный блок кода, который выполняет одну понятную задачу. Она помогает:

  • не повторять одинаковый код;
  • дать действию понятное имя;
  • проверить часть программы отдельно;
  • сделать main коротким и читаемым.

Например, вместо нескольких одинаковых строк вывода можно создать функцию:

package main

import "fmt"

func printWelcome() {
	fmt.Println("Добро пожаловать в Task Manager")
}

func main() {
	printWelcome()
}

func объявляет функцию, printWelcome — её имя, а круглые скобки содержат параметры. В этом примере параметров и возвращаемого результата нет.

Параметры

Параметры передают функции значения, с которыми она должна работать. Имя параметра записывают перед его типом:

func printTaskTitle(title string) {
	fmt.Println("Задача:", title)
}

Вызов передаёт аргумент:

func main() {
	printTaskTitle("Купить молоко")
}

Одна функция может принимать несколько параметров одного типа. Их можно записать через запятую:

func printTask(title string, priority int) {
	fmt.Println("Задача:", title)
	fmt.Println("Приоритет:", priority)
}

Количество, порядок и типы аргументов при вызове должны совпадать с объявлением:

printTask("Купить молоко", 2)

В Go аргументы передаются в функцию по значению: параметр получает собственную копию значения. Работа с указателями и изменением сложных данных появится в следующих главах.

Один возвращаемый результат

После списка параметров можно указать тип результата. Функция возвращает значение через return:

func priorityLabel(priority int) string {
	if priority == 1 {
		return "низкий"
	}

	if priority == 2 {
		return "средний"
	}

	if priority == 3 {
		return "высокий"
	}

	return "неизвестный"
}

Результат вызова можно сохранить в переменную:

label := priorityLabel(2)
fmt.Println(label) // средний

Функция с объявленным результатом должна вернуть значение на каждом возможном пути выполнения. В примере последний return обрабатывает все значения, кроме 1, 2 и 3.

Ранний return

return завершает выполнение функции сразу. Это удобно для валидации: сначала возвращаем результат при первой найденной проблеме, а успешный путь оставляем в конце.

func validateTitle(title string) bool {
	if len(title) == 0 {
		return false
	}

	if len(title) > 120 {
		return false
	}

	return true
}

Такую проверку можно сделать короче одним выражением:

func validateTitle(title string) bool {
	return len(title) > 0 && len(title) <= 120
}

Оба варианта корректны. Первый удобнее, если позже понадобится разные сообщения для разных ошибок.

Несколько результатов

Go-функция может вернуть несколько значений. Типы результата указывают в скобках:

func validatePriority(priority int) (bool, string) {
	if priority < 1 || priority > 3 {
		return false, "приоритет должен быть от 1 до 3"
	}

	return true, ""
}

При вызове каждому результату соответствует своя переменная:

isValid, message := validatePriority(4)

fmt.Println(isValid) // false
fmt.Println(message) // приоритет должен быть от 1 до 3

Если один результат сейчас не нужен, используйте _:

isValid, _ := validatePriority(2)
fmt.Println(isValid) // true

Не заменяйте _ обычной переменной, которую не будете использовать: Go выдаст ошибку о неиспользуемой переменной.

Именованные результаты

Результат можно назвать в объявлении функции:

func validatePriority(priority int) (isValid bool, message string) {
	if priority < 1 || priority > 3 {
		return false, "приоритет должен быть от 1 до 3"
	}

	return true, ""
}

Имена делают сигнатуру понятнее, но не обязательны. В начале лучше использовать обычные результаты и явно указывать значения в return. Именованные результаты пригодятся, когда делают API функции понятнее, а не просто сокращают код.

Область видимости

Параметры и переменные внутри функции существуют только в этой функции:

func printTaskTitle(title string) {
	formattedTitle := "Задача: " + title
	fmt.Println(formattedTitle)
}

func main() {
	printTaskTitle("Купить молоко")
	// fmt.Println(formattedTitle) // ошибка: переменная существует только внутри функции
}

Функция может обращаться к импортированным пакетам, например fmt, но не видит локальные переменные другой функции.

Соберём валидацию задачи

Теперь вынесем проверку Task Manager API в отдельные функции:

package main

import "fmt"

func validateTitle(title string) (bool, string) {
	if len(title) == 0 {
		return false, "название задачи не должно быть пустым"
	}

	if len(title) > 120 {
		return false, "название задачи слишком длинное"
	}

	return true, ""
}

func validatePriority(priority int) (bool, string) {
	if priority < 1 || priority > 3 {
		return false, "приоритет должен быть от 1 до 3"
	}

	return true, ""
}

func main() {
	title := "Купить молоко"
	priority := 2

	if isValid, message := validateTitle(title); !isValid {
		fmt.Println(message)
		return
	}

	if isValid, message := validatePriority(priority); !isValid {
		fmt.Println(message)
		return
	}

	fmt.Println("Задачу можно создать")
}

main теперь управляет последовательностью действий, а каждая функция отвечает только за свою проверку. Пока вместо типа error мы возвращаем bool и текст. Обработку ошибок в идиоматичном Go подробно разберём в отдельной главе.

Частые ошибки

Вызов до объявления — не проблема

В Go функцию можно вызвать до её текстового объявления в файле. Важнее, чтобы имя и сигнатура совпадали:

func main() {
	fmt.Println(priorityLabel(2))
}

func priorityLabel(priority int) string {
	return "средний"
}

Результат не возвращён

func priorityLabel(priority int) string {
	if priority == 1 {
		return "низкий"
	}

	// ошибка: missing return
}

Добавьте результат для всех оставшихся случаев.

Неверное число аргументов

func printTask(title string, priority int) {
	// ...
}

// printTask("Купить молоко") // ошибка: не передан priority

Путаница return и fmt.Println

fmt.Println выводит данные в терминал, а return отдаёт результат вызывающему коду. Функция может делать одно, другое или оба действия, но для проверяемой логики обычно лучше вернуть результат, а вывести его в main.
