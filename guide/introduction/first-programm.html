Первая программа: Hello World

В предыдущем разделе мы привели простейшую программу — "Hello World". Теперь разберём её подробнее: что происходит шаг за шагом, из каких базовых частей она состоит, и почему Go работает именно так. Это поможет понять фундамент языка. Затем опишем процесс компиляции в бинарный файл (go build) и что происходит после этого на каждой платформе (Windows, macOS, Linux).

Используй VS Code, скопируй код и попробуй запустить — это лучший способ закрепить информацию.

Программа:

// package main — каждый файл начинается с package
package main

// Импорт пакетов (fmt для печати)
import "fmt"

// Главная функция — точка входа
func main() {
    fmt.Println("Hello, Go!")  // Вывод в консоль
}

Базовые части программы: Из чего состоит код?

Инфо

Go-программа — это набор файлов в пакете (package). Каждый файл начинается с объявления пакета, импортов и определений (функций, типов и т.д.).

Разберём код по строкам

Строка 1: Комментарий

// package main — каждый файл начинается с package

Это однострочный комментарий (начинается с //). Go игнорирует его при компиляции. Комментарии полезны для документации. Есть и многострочные: /* ... */.

Почему? Чтобы код был читаемым для людей. В реальных проектах добавляй комментарии для сложных частей.

Строка 2: Объявление пакета

package main

Каждый Go-файл должен начинаться с package <name>. Здесь main — специальный пакет, обозначающий исполняемую программу (executable). Другие пакеты (например, package utils) — для библиотек.

Что происходит? Go группирует код в пакеты для модульности. main — точка входа в приложение. Без него программа не запустится как самостоятельная.

Аналогия: Пакет — как глава в книге. main — это "введение", где начинается история.

Строка 5: Импорт пакетов

import "fmt"

import подключает внешние пакеты (библиотеки). Здесь fmt — стандартный пакет для форматированного ввода/вывода (format). Без импорта ты не можешь использовать fmt.Println.

Что происходит? При компиляции Go ищет пакет в стандартной библиотеке (GOROOT) или в зависимостях (GOPATH/modules). Если пакета нет — ошибка.

Почему? Go поощряет переиспользование кода. Стандартная библиотека богата (net/http для серверов, os для файлов и т.д.). Для нескольких импортов используй скобки ():

import (
    "fmt"
    "os"
)

Совет: Не импортируй лишнее — Go компилятор выдаст ошибку на unused imports.

Строка 8-10: Определение функции

func main() {
    fmt.Println("Hello, Go!")
}

func — ключевое слово для функций. main() — специальная функция: точка входа, откуда начинается выполнение. Она не принимает аргументов и ничего не возвращает (void).

Внутри: fmt.Println("Hello, Go!") — вызов функции Println из пакета fmt. Она выводит строку в стандартный вывод (консоль) и добавляет новую строку (\n).

Что происходит шаг за шагом при запуске?

  1. Go-рантайм (runtime) запускает функцию main().
  2. fmt.Println берёт аргумент ("Hello, Go!") — это строка (string literal).
  3. Она конвертирует строку в байты (UTF-8) и отправляет в stdout (стандартный вывод ОС).
  4. Программа завершается (exit code 0, если без ошибок).

Аналогия: main() — как кнопка "Старт" в приложении. Без неё ничего не запустится.

Почему нет возврата? В Go main не возвращает значение — ошибки обрабатываются внутри (panic или os.Exit).

Общий процесс выполнения программы:

  • Когда ты запускаешь go run main.go, Go компилирует код в память (временно) и исполняет.
  • Если ошибок нет (синтаксис, типы) — вывод в консоль.
  • Go — статически типизированный: все типы проверяются на этапе компиляции, нет runtime-ошибок типов (как в Python).

Советы по отладке

  • Если ошибка: Читайте сообщение (Go даёт точные: "undefined: fmt" если без импорта).
  • Добавьте fmt.Printf("Debug: %s\n", variable) для отладки.

Компиляция в бинарный файл: Что такое go build и зачем?

Инфо

Go — компилируемый язык: код преобразуется в машинный код (бинарник), который ОС исполняет напрямую (без интерпретатора как в Python). Команда go build создаёт исполняемый файл.

Что происходит при go build?

  • Go-компилятор (gc) анализирует код: проверяет синтаксис, типы, импорты.
  • Линкует с стандартной библиотекой (включая runtime для GC, goroutines).
  • Производит оптимизированный бинарник: статически слинкованный (все зависимости внутри, нет DLL/shared libs).
  • Результат: Один файл, который работает на целевой ОС без установки Go.

Преимущества: Быстрый запуск, портативность (скопируй бинарник и запусти на другой машине той же ОС/архитектуры).

Команда: В директории с main.go выполни go build — создаст файл (main.exe на Windows, main на Unix-like).

Кросс-компиляция: GOOS=linux GOARCH=amd64 go build — скомпилируй для Linux на Windows.

Теперь разберём, что происходит после компиляции для каждой системы. Предполагаем, что ты скомпилировал программу в бинарник (например, hello или hello.exe).

Для Windows

Инфо

Бинарник: Файл с расширением .exe (например, main.exe). Это PE (Portable Executable) формат — стандарт Windows для исполняемых файлов.

Что происходит после компиляции?

  1. go build создаёт main.exe в текущей директории (размер ~2-5 MB, включает runtime).
  2. Чтобы запустить: Двойной клик на main.exe (откроется консоль и выведет "Hello, Go!", затем закроется) или в cmd: ./main.exe.
  3. ОС (Windows) загружает PE-файл в память: Разбирает заголовки, аллоцирует память, запускает entry point (которая вызывает Go-runtime).
  4. Go-runtime инициализируется: Настраивает GC, scheduler для goroutines (даже если их нет).
  5. Выполняется main(), вывод в консоль через WinAPI (stdout).
  6. Программа завершается, runtime чистит память (GC), ОС освобождает ресурсы.

Особенности: Бинарник самодостаточный — работает без Go на машине. Если консоль закрывается быстро, добавь time.Sleep или читай ввод (fmt.Scanln()).

Проверка: main.exe /? — не сработает, т.к. нет args, но можно добавить с os.Args.

Для macOS

Инфо

Бинарник: Файл без расширения (например, main). Это Mach-O формат — стандарт macOS для исполняемых файлов (аналог ELF в Linux).

Что происходит после компиляции?

  1. go build создаёт main в текущей директории (размер ~2-5 MB).
  2. Чтобы запустить: В Terminal ./main (сделай исполняемым: chmod +x main, если нужно).
  3. ОС (macOS/Darwin) загружает Mach-O: Парсит сегменты (text, data), маппит в память, вызывает entry point.
  4. Go-runtime стартует: Инициализирует GC, scheduler (интегрируется с mach threads).
  5. Выполняется main(), вывод в stdout через syscalls (Darwin API).
  6. Завершение: Runtime выгружает, ОС чистит (no leaks благодаря GC).

Особенности: На Apple Silicon (M1+) — нативный arm64. Бинарник портативен: Скопируй на другой Mac и запусти без Go. Для GUI — используй пакеты вроде fyne.

Проверка: file main — покажет "Mach-O 64-bit executable arm64".

Для Linux

Инфо

Бинарник: Файл без расширения (например, main). Это ELF (Executable and Linkable Format) — стандарт Unix-like для бинарников.

Что происходит после компиляции?

  1. go build создаёт main в текущей директории (размер ~2-5 MB).
  2. Чтобы запустить: ./main (сделай исполняемым: chmod +x main).
  3. ОС (Linux kernel) загружает ELF: Читает header, загружает сегменты в виртуальную память, устанавливает stack/heap, вызывает _start (которая ведёт к Go-runtime).
  4. Go-runtime инициализируется: Настраивает GC, использует pthreads для goroutines.
  5. Выполняется main(), вывод в stdout через syscalls (write to fd 1).
  6. Завершение: Runtime вызывает exit, kernel освобождает процессы.

Особенности: Бинарник статический — работает на любом Linux без зависимостей (glibc etc.). Для контейнеров (Docker) — идеально (scratch image).

Проверка: file main — "ELF 64-bit LSB pie executable, x86-64".

Общие советы по компиляции:

go build -o customname # укажи имя бинарника
go build -ldflags="-s -w" # для релиза уменьши размер (strip symbols)
  • Ошибки: Если "no Go files" — убедись в package main.
  • Кросс-платформа: Скомпилируй на одной ОС для другой — Go поддерживает 20+ платформ.
