# Политика безопасности

## Поддерживаемые версии

Поддерживаются актуальная версия сайта на ветке `master` и развёрнутый GitHub Pages-сайт. Исторические commits, старые PWA-кэши и локальные копии могут не получать исправления.

## Как сообщить об уязвимости

Не создавайте публичный issue для уязвимости, которая может затронуть посетителей сайта, workflow GitHub Actions, secrets, PWA, зависимости или GitHub Pages deployment.

Используйте [GitHub private security advisory](https://github.com/DanilChugaev/go-book/security/advisories/new). В сообщении укажите:

- краткое описание и потенциальный эффект;
- затронутые URL, файлы, workflow или версии зависимостей;
- воспроизводимые шаги или proof of concept;
- возможные меры снижения риска, если они известны.

Не публикуйте токены, cookies, личные данные или secrets в отчёте. Если private advisory недоступен, откройте обычный issue **без технических деталей уязвимости** с просьбой установить приватный канал связи.

## Что ожидать

Maintainер подтвердит получение сообщения, оценит проблему, при необходимости задаст уточняющие вопросы и подготовит исправление. Срок зависит от серьёзности и воспроизводимости проблемы. Просьба не раскрывать детали публично до согласования исправления.

## Область действия

Политика относится к репозиторию, GitHub Actions workflow, опубликованному сайту и его PWA-конфигурации. Учебные фрагменты кода сами по себе не являются готовыми production-сервисами; перед применением в реальных системах их нужно адаптировать к конкретной модели угроз и инфраструктуре.
