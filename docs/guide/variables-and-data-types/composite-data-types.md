# Составные типы данных

В предыдущих частях главы мы разобрали простые (basic/predeclared) типы: числовые, bool, string. Теперь углубимся в **составные типы** (composite types).

> Это типы, которые строятся из других типов и позволяют создавать сложные структуры данных.

Go предоставляет их для работы с коллекциями, объектами и ссылками. Мы разберём каждый тип подробно: синтаксис, как работает, аналогии, примеры, подводные камни и когда использовать.

Составные типы в Go:
- Array (массив).
- Slice (слайс).
- Map (мапа).
- Struct (структура).
- Pointer (указатель).
- Function type (тип функции).
- Channel (канал).
- Interface (интерфейс).

Они "составные", потому что определяются пользователем или строятся на основе других типов. В отличие от простых, они часто reference types (передаются по ссылке, не копируются целиком).

## Составные типы: Общий обзор

Составные типы позволяют комбинировать данные. Например, array — фиксированная коллекция, struct — как объект с полями. Многие из них (slice, map, chan) — reference types: при присваивании/передаче копируется только "ссылка" (указатель + метаданные), а не данные.

**Таблица составных типов:**
| Тип         | Описание                             | Reference type? | Когда использовать                   |
|-------------|--------------------------------------|-----------------|--------------------------------------|
| Array       | Фиксированная последовательность     | Нет (value)     | Когда размер известен заранее        |
| Slice       | Динамическая "ссылка" на array       | Да              | Коллекции с изменяемым размером      |
| Map         | Ключ-значение (hash-таблица)         | Да              | Ассоциативные данные                 |
| Struct      | Составной объект с полями            | Нет (value)     | Модели данных (как классы)           |
| Pointer     | Адрес в памяти                       | Да              | Изменения по ссылке, nil-значения    |
| Function    | Тип для функций (сигнатура)          | Да              | Callback'ы, functional programming   |
| Channel     | Канал для concurrency                | Да              | Общение между goroutines             |
| Interface   | Контракт методов                     | Да              | Полиморфизм, duck typing             |

Далее поверхностно разберём каждый из них. В последующих главах углубимся в них более детально.

## Array (Массив)

> Фиксированная последовательность элементов одного типа. Размер — часть типа ([N]T), так что [3]int и [4]int — разные типы. Массивы — value types: копируются при присваивании.

**Аналогия**: Фиксированная коробка с отсеками — нельзя добавить/убрать отсек.

**Синтаксис**:

```go
[N]T{val1, val2, ...}
```

**Пример**:

```go
var arr [3]int = [3]int{1, 2, 3}  // Или arr := [3]int{1, 2, 3}
fmt.Println(arr[1])               // 2 (индекс от 0)
arr[2] = 4                        // Изменение

// Многомерный
matrix := [2][2]int{{1, 2}, {3, 4}}
fmt.Println(matrix[1][0])        // 3

// Итерация
for i := 0; i < len(arr); i++ {
    fmt.Println(arr[i])
}
```

**Подводные камни**: Фиксированный размер — нельзя append. Копирование большого array дорого по памяти. Индекс за пределами — panic.

**Когда использовать**: Редко напрямую — лучше slice. Для фиксированных структур (например, [3]float64 для RGB).

## Slice (Слайс)

> Динамическая "вью" на array. Структура: указатель на данные + len (длина) + cap (ёмкость). Reference type — изменения видны везде.

**Аналогия**: Окно на массив — можно сдвигать/расширять, но не менять underlying array без realloc.

**Синтаксис**:

```go
[]T{val1, val2, ...}

// или
make([]T, len, cap)
```

**Пример**:

```go
s := []string{"apple", "banana"}  // len=2, cap=2
s = append(s, "cherry")           // [apple banana cherry], cap может вырасти

sub := s[1:3]                     // Слайсинг: ["banana", "cherry"] (от 1 до 3, не включая 3)
sub[0] = "orange"                 // Изменит оригинал s!

fmt.Println(len(s), cap(s))       // 3 4 (cap удвоилась автоматически)

// Итерация с range
for i, v := range s {
    fmt.Println(i, v)
}
```

**Подводные камни**: Append может realloc — старые слайсы могут ссылаться на старые данные. Shared underlying array — изменения в sub влияют на s.

**Когда использовать**: Везде для списков (замена array). Эффективно благодаря copy-on-write.

## Map (Мапа)

> Неупорядоченная коллекция ключ-значение. Ключи — comparable типы (int, string, etc., но не slice/map/func). Reference type.

**Аналогия**: Телефонная книга — по имени (ключ) находишь номер (значение).

**Синтаксис**:

```go
map[K]V{key1: val1, ...}
// или
make(map[K]V)
```

**Пример**:

```go
m := map[string]int{"age": 30, "height": 180}
m["weight"] = 70                  // Добавление
delete(m, "height")               // Удаление

val, ok := m["age"]               // 30, true (ok — существует ли ключ)
if !ok {
    fmt.Println("Ключ не найден")
}

// Итерация
for k, v := range m {
    fmt.Println(k, v)
}
```
- **Подводные камни**: Nil-map — нельзя писать (panic). Порядок итерации случайный. Ключи должны быть hashable.
- **Когда использовать**: Для словарей, кэшей, конфигов.

## Struct (Структура)

> Составной тип с именованными полями разных типов. Value type, но часто используется с pointer.

**Аналогия**: Анкета с полями (имя, возраст).

**Синтаксис**:

```go
type Name struct {
    Field1 Type1;
    Field2 Type2;
}
```

**Пример**:

```go
type Point struct {
    X, Y int  // Поля (можно anonymous/embedded)
}

p := Point{X: 10, Y: 20}
p.X = 15                          // Доступ по .

// Анонимная struct
anon := struct { Name string }{Name: "Temp"}
```

**Подводные камни**: Структуры копируются — для больших используй pointer. Поля с большой буквы — exported.

**Когда использовать**: Для моделей данных (Person, Car).

## Pointer (Указатель)

> Тип *T — адрес значения типа T. Для изменений по ссылке и nil.

**Аналогия**: Указатель на коробку, а не копия коробки.

**Пример**:
```go
var ptr *int
i := 42
ptr = &i
*ptr = 50  // i=50
```

**Подводные камни**: Nil dereference — panic. (Подробно в отдельной главе).

**Когда использовать**: Для мутабельности, опциональных значений.

## Function type (Тип функции)

> Тип func(params) returns — для хранения функций как значений.

**Аналогия**: Рецепт как объект.

**Пример**:

```go
var f func(int) int = func(x int) int {
    return x*2
}

f(5) // 10
```

**Подводные камни**: Сигнатуры должны совпадать.

**Когда использовать**: Callback'ы, closures.

## Channel (Канал)

> Тип chan T для общения в concurrency. Make(chan T, buffer).

**Аналогия**: Труба между goroutines.

**Пример**:

```go
ch := make(chan int);
ch <- 42;
val := <-ch
```

**Подводные камни**: Nil-chan — deadlock. (Подробно в concurrency).

**Когда использовать**: С goroutines.

## Interface (Интерфейс)

> Тип interface { methods }. Реализуется implicitly.

**Аналогия**: Контракт: "если есть метод Area() — это Shaper".

**Пример**:

```go
type Reader interface {
    Read()
}

var r Reader = &File{}
```

**Подводные камни**: Nil interface vs interface with nil value.

**Когда использовать**: Полиморфизм.

## Типичные ошибки с составными типами
1. Index out of range в array/slice — panic.
2. Write to nil map/chan — panic.
3. Копирование struct с pointer — shallow copy (ссылки общие).
4. Итерация map — порядок случайный, не полагайся на него.
