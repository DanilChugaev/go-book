# Рекомендации по коду: ошибки

- Возвращайте `error` последним результатом функции, если операция может не выполниться.
- Проверяйте ошибку сразу и используйте ранний `return`, чтобы не строить глубокие вложенности.
- Создавайте известные причины как переменные `Err...`, если вызывающему коду нужно их распознавать.
- Добавляйте контекст через `fmt.Errorf` и `%w`, не теряя исходную причину.
- Проверяйте причины через `errors.Is`, а не сравнением текста `err.Error()`.
- Не используйте `panic` для обычных ошибок валидации, файловой системы или сети.

## Чек-лист

Ошибка содержит полезный контекст, известные причины доступны для `errors.Is`, а после неудачи код не продолжает успешный сценарий по ошибке.
