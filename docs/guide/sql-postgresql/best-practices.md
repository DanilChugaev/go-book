# Рекомендации по коду: SQL и PostgreSQL

- Открывайте `*sql.DB` один раз при старте, настраивайте пул и проверяйте доступность через `PingContext`.
- Передавайте context в каждую операцию базы: `QueryContext`, `QueryRowContext`, `ExecContext` и `BeginTx`.
- Никогда не собирайте пользовательские значения конкатенацией в SQL; используйте placeholders `$1`, `$2`.
- Сразу после `QueryContext` откладывайте `rows.Close` и всегда проверяйте `rows.Err` после обхода.
- Преобразуйте `sql.ErrNoRows` в ошибку предметной области, а не раскрывайте SQL-детали HTTP-слою.
- Храните изменения схемы в неизменяемых SQL-миграциях Goose и применяйте их одинаково локально, в CI и production.
- Используйте транзакции только там, где несколько изменений должны быть атомарными.
- Не храните DATABASE_URL или пароли в Git и не записывайте их целиком в логи.
- Проверяйте репозиторий интеграционными тестами против отдельной test-БД; не запускайте destructive SQL против development или production базы.
- Используйте DBeaver для диагностики схемы и данных, но не для ручных изменений, которые должны быть миграциями.

## Чек-лист

API подключается к PostgreSQL через настроенный пул, схема создаётся Goose-миграциями, CRUD передаёт context и использует параметры SQL, ошибки отсутствия ресурса становятся `404` на HTTP-границе, а реальный PostgreSQL-репозиторий проверен на отдельной тестовой базе.
