# Рекомендации по коду: время и дедлайны

- Храните и передавайте моменты времени в UTC, особенно в JSON и API.
- Используйте `time.RFC3339` для машинного обмена, а пользовательский layout — только для отображения.
- Не сравнивайте `time.Time` через `==` для бизнес-логики; используйте `Before`, `After` и `Equal`.
- Передавайте `now` параметром в методы дедлайна: код станет детерминированным и тестируемым.
- Явно обрабатывайте отсутствие дедлайна через `IsZero`.
- Различайте интервал `time.Duration` и календарные операции: для календарных дней и месяцев нужен `AddDate`.
- Проверяйте дедлайны с фиксированным `now`, созданным через `time.Date`, а не через `time.Now()`.
- После JSON round-trip сравнивайте моменты через `time.Equal`.

## Чек-лист

В API нет неявной локальной зоны, дата парсится по явному layout, дедлайн без значения не ошибочно считается просроченным, а тесты времени не зависят от момента запуска.
