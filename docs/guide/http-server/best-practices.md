# Рекомендации по коду: HTTP API на `net/http`

- Регистрируйте маршруты с конкретными HTTP-методами и держите их в одном месте.
- Сначала устанавливайте response headers, затем статус через `WriteHeader`, и только потом записывайте body.
- Отдавайте JSON через общий helper с `Content-Type: application/json; charset=utf-8`.
- Проверяйте path-параметры, размер body, синтаксис JSON и входные значения до вызова service.
- Для входных JSON используйте отдельные request-типы; не позволяйте клиенту задавать служебные поля модели, например ID.
- Передавайте `r.Context()` в service, repository и внешние операции.
- Не смешивайте маршрутизацию, HTTP-статусы, mutex и бизнес-правила в одном handler.
- Логируйте внутреннюю ошибку с контекстом, а клиенту возвращайте безопасное стабильное сообщение.
- Тестируйте handlers через `httptest`; проверяйте статус, заголовки, JSON и вызов service без запуска сервера на порту.

## Чек-лист

Каждый маршрут имеет понятный HTTP-контракт, невалидный вход возвращает `400`, отсутствующий ресурс — `404`, неожиданные сбои — безопасный `500`, а HTTP-слой можно заменить на Gin без переписывания service и repository.
