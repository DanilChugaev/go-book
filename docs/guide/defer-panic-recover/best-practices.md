# Рекомендации по коду: `defer`, `panic` и `recover`

- Ставьте `defer Close`, `defer Unlock` и `defer cancel` сразу после успешного захвата ресурса.
- Не откладывайте вызов до проверки ошибки создания ресурса: указатель может быть `nil`.
- Помните порядок LIFO, если несколько defer освобождают зависимые ресурсы.
- Возвращайте `error` для ожидаемых сбоев: некорректного ввода, отсутствия файла, сетевой или SQL-ошибки.
- Используйте `panic` только для нарушенного внутреннего инварианта или ситуации, которую текущий уровень не может корректно обработать.
- Размещайте `recover` только на явной границе и обязательно логируйте или возвращайте информацию о причине panic.

## Чек-лист

Все открытые ресурсы освобождаются, panic не используется для валидации, а recover не скрывает ошибку, которую нужно исправить в коде.
