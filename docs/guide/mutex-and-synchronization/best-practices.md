# Лучшие практики: mutex и синхронизация

- Защищайте одним мьютексом все связанные операции над общим состоянием, а не отдельные строки кода случайно.
- После `Lock` сразу пишите `defer Unlock`; после `RLock` — `defer RUnlock`.
- Используйте `RLock` только для чтения. Любое изменение требует обычного `Lock`.
- Держите критическую секцию короткой: не выполняйте под мьютексом запись файла, сеть или долгие вычисления.
- Не копируйте используемые `Mutex`, `RWMutex` и структуры, которые их содержат.
- Регулярно запускайте concurrent-код с `go test -race ./...` или `go run -race .`.

## Чек-лист

Каждое общее изменяемое поле имеет ясный механизм синхронизации, все пути после блокировки освобождают мьютекс, а race detector запускается в тестах.
