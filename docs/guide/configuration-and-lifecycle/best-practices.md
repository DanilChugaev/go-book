# Рекомендации по коду: конфигурация и жизненный цикл

- Читайте и проверяйте конфигурацию один раз при старте; не обращайтесь к env из handlers и service.
- Обязательные значения валидируйте явно, а fallback используйте только там, где он безопасен и документирован.
- Храните локальные значения в `.env`, коммитьте только `.env.example`, а `.env` всегда добавляйте в `.gitignore`.
- Не выводите целиком config в логи: будущие поля могут содержать секреты.
- Используйте явный `http.Server` и выбирайте read/write/idle timeout по характеру API.
- Обрабатывайте `SIGINT` и `SIGTERM` через `signal.NotifyContext`; вызывайте `stop` для освобождения ресурсов.
- Для shutdown создавайте отдельный ограниченный context от `context.Background()`.
- Сначала выполняйте `server.Shutdown`, затем закрывайте базу данных, файлы и остальные зависимости.
- Не вызывайте `os.Exit` за пределами `main` и не используйте его в defer.
- Тестируйте разбор конфигурации через `t.Setenv` без параллельных тестов и реального `.env`.

## Чек-лист

Приложение не запускается с неверной конфигурацией, секреты не попадают в Git и логи, HTTP-сервер имеет защитные таймауты, а `SIGINT`/`SIGTERM` останавливают приём новых запросов и дают активной работе ограниченное время на завершение.
