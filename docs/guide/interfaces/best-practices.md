# Рекомендации по коду: интерфейсы

- Объявляйте интерфейс у потребителя поведения, а не заранее рядом с типом «на всякий случай».
- Делайте интерфейсы маленькими: один-два метода обычно лучше большого «универсального» контракта.
- Используйте интерфейс, когда реально нужны несколько возможных реализаций или тестируемая граница зависимости.
- Не создавайте интерфейс для каждого типа автоматически; конкретный тип часто проще и понятнее.
- Помните, что методы с pointer receiver реализуются только указателем `*T`.
- Не передавайте nil-указатель в интерфейс, если вызывающий код ожидает обычный nil.

## Чек-лист

Интерфейс выражает конкретную потребность функции, его можно реализовать без лишних методов, а выбор между `T` и `*T` осознан.
