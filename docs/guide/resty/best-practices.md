# Рекомендации по коду: Resty

- Используйте Resty в инфраструктурном HTTP-клиенте, а не в service или доменной модели.
- Создавайте один настроенный `resty.Client` с base URL, timeout и безопасными общими заголовками.
- Передавайте `context.Context` в каждый request через `SetContext`.
- Принимайте только оговорённые успешные статусы: для этого API — `2xx`, а не просто «не ошибка Resty».
- Декодируйте внешний ответ в отдельный DTO и проверяйте его бизнес-допустимость.
- Не логируйте токены, cookies, headers авторизации и полные тела запросов или ответов.
- Включайте retry только для явно безопасных идемпотентных сценариев с лимитом, backoff, context и проверяемым условием.
- Для строгого контроля размера и структуры response body предпочитайте реализацию на стандартном `net/http`.
- Тестируйте Resty-клиент через `httptest.Server`, включая статусы, некорректный JSON и отмену context.

## Чек-лист

Resty уменьшает повторяющийся transport-код, но client по-прежнему передаёт context, проверяет только разрешённые статусы и данные внешнего сервиса, не раскрывает секреты в логах, а service зависит только от интерфейса.
