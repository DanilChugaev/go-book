# Рекомендации по коду: Docker и локальное окружение

- Собирайте Go-приложение через multi-stage Dockerfile и копируйте в final image только нужный бинарник.
- Не запускайте production container от root, если для этого нет явной причины.
- Держите Docker build context маленьким: `.git`, `.env`, документация, временные файлы и coverage не должны попадать в image.
- Разделяйте `.gitignore` и `.dockerignore`: они решают разные задачи и оба нужны.
- Передавайте настройки через env и Compose, а не записывайте адреса, пароли и токены в Dockerfile.
- Внутри Compose обращайтесь к сервисам по их именам, например `postgres`, а не через `localhost`.
- Сохраняйте данные PostgreSQL в named volume и используйте `down -v` только когда осознанно нужен чистый state.
- Публикуйте PostgreSQL на `127.0.0.1` только для локальных инструментов; production-БД не должна быть доступна из внешней сети по умолчанию.
- Используйте health-check как сигнал готовности зависимости, но всё равно обрабатывайте ошибки подключения в приложении.
- Проверяйте итоговый YAML через `docker compose config`, а API — через `/healthz` после запуска.

## Чек-лист

Окружение поднимается одной командой, API и PostgreSQL используют предсказуемые версии, БД сохраняет данные в volume, локальные secrets не попадают в image и Git, а приложение готово подключиться к service `postgres` в следующей главе.
