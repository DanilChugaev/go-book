# Лучшие практики: методы

- Размещайте поведение сущности рядом с её типом: `Task.Summary`, `Task.IsValid`.
- Выбирайте value receiver для небольших неизменяемых операций чтения.
- Не создавайте метод с value receiver, если его имя обещает изменение исходной структуры.
- Сохраняйте единообразие receiver для одного типа; исключения должны быть понятны и обоснованы.
- Пусть методы бизнес-логики возвращают значение или ошибку, а вывод в терминал остаётся на уровне `main` или handler.
- Не добавляйте метод только потому, что он технически возможен: иногда обычная функция лучше выражает независимую операцию.

## Чек-лист

Методы читаются как действия модели, не смешивают вывод и бизнес-логику, а их receiver соответствует тому, меняют ли они данные.
