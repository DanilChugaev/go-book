# Рекомендации по коду: итоговый проект

- Держите `main` тонким: он загружает config, собирает зависимости и управляет жизненным циклом.
- Сохраняйте направление зависимостей от HTTP и инфраструктуры к service и интерфейсам, а не наоборот.
- Считайте README частью продукта: обновляйте его в том же pull request, что и команды, env или HTTP-контракт.
- Закрепляйте публичные статусы и JSON-форматы handler-тестами.
- Меняйте схему PostgreSQL только миграциями, а не вручную через DBeaver.
- Перед merge запускайте vet, unit, race, integration tests, Compose validation и Docker build.
- Деплойте проверенный SHA image, проверяйте `/healthz` и храните известный рабочий тег для rollback.
- Не добавляйте новые функции без контракта, миграционного плана, тестов и наблюдаемости.
- Не усложняйте проект заранее: выбирайте одно улучшение, которое решает понятную пользовательскую проблему.

## Чек-лист

Task Manager API запускается в чистом окружении по README, имеет разделённые слои, тестируемый HTTP-контракт, воспроизводимую PostgreSQL-схему, безопасное Docker/CI/CD-окружение и понятный план дальнейшего развития.
