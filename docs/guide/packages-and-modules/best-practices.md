# Лучшие практики: пакеты и модули

- Создавайте один `go.mod` на независимое приложение или библиотеку.
- Пусть package name коротко описывает ответственность и обычно совпадает с именем папки.
- Импортируйте пакет по module path, а не через `./` или `../`.
- Экспортируйте только API, который нужен другим пакетам; вспомогательные детали оставляйте со строчной буквы.
- Используйте `internal` для кода, который является деталью конкретного приложения, а не публичной библиотекой.
- Не дробите проект на много пакетов преждевременно: одна связная область логики может жить в одном пакете.

## Чек-лист

Зависимости пакетов направлены понятно, `main` не содержит модель и бизнес-логику, а внутренние детали не становятся экспортируемым API без причины.
