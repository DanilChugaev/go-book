# Структуры: модель задачи

## Цель урока

Научиться объединять связанные данные в собственный тип, создавать и изменять структуры, а также хранить задачи в слайсе и map.

До этого Task Manager API хранил название, приоритет и признак выполнения в отдельных переменных. Но эти значения относятся к одной сущности — задаче. Структура поможет хранить их вместе.

## Что такое структура

Структура (`struct`) — тип с именованными полями разных типов. Сначала объявим тип `Task`:

```go
type Task struct {
	ID        int
	Title     string
	Priority  int
	Completed bool
}
```

Теперь `Task` — собственный тип. Он описывает одну задачу с четырьмя полями:

| Поле | Тип | Назначение |
| --- | --- | --- |
| `ID` | `int` | Уникальный идентификатор задачи |
| `Title` | `string` | Название задачи |
| `Priority` | `int` | Уровень приоритета от 1 до 3 |
| `Completed` | `bool` | Признак выполнения |

Названия полей начинаются с заглавной буквы. Позже, при изучении пакетов, мы узнаем, что такие поля доступны коду из других пакетов. Внутри текущего `main` это не влияет на работу, но это распространённый стиль для моделей, которые в будущем будут участвовать в API.

## Создание структуры

Структуру можно создать литералом с именами полей:

```go
task := Task{
	ID:        1,
	Title:     "Купить молоко",
	Priority:  2,
	Completed: false,
}
```

Имена полей делают код понятным и позволяют не зависеть от их порядка. Это рекомендуемый способ создания структуры.

Можно указать не все поля. Остальные получат нулевые значения:

```go
task := Task{
	ID:    1,
	Title: "Купить молоко",
}

fmt.Println(task.Priority)  // 0
fmt.Println(task.Completed) // false
```

Можно создать нулевое значение всей структуры:

```go
var task Task

fmt.Println(task) // {0  0 false}
```

Нулевое значение структуры уже существует и безопасно для чтения её полей. Однако нулевые значения не всегда соответствуют правилам приложения: например, задача с пустым названием и ID `0` не должна считаться корректной.

## Доступ и изменение полей

Для чтения и изменения поля используйте точку:

```go
task := Task{
	ID:        1,
	Title:     "Купить молоко",
	Priority:  2,
	Completed: false,
}

fmt.Println(task.Title) // Купить молоко

task.Title = "Купить продукты"
task.Completed = true

fmt.Println(task)
```

Структура — значение. При присваивании одной переменной другой копируются все поля:

```go
original := Task{
	ID:       1,
	Title:    "Купить молоко",
	Priority: 2,
}
copyOfTask := original

copyOfTask.Title = "Купить продукты"

fmt.Println(original.Title)   // Купить молоко
fmt.Println(copyOfTask.Title) // Купить продукты
```

Это удобно, когда нужна независимая копия, но важно помнить об этом при передаче структуры в функцию. Указатели и изменение структуры через функции разберём позднее.

## Слайс задач

Слайс может хранить структуры так же, как строки или числа:

```go
tasks := []Task{
	{
		ID:       1,
		Title:    "Купить молоко",
		Priority: 2,
	},
	{
		ID:       2,
		Title:    "Оплатить интернет",
		Priority: 3,
	},
}
```

Добавить задачу можно через `append`:

```go
tasks = append(tasks, Task{
	ID:       3,
	Title:    "Прочитать книгу",
	Priority: 1,
})
```

Для вывода используйте `range`:

```go
for _, task := range tasks {
	fmt.Printf("%d. %s — приоритет %d\n", task.ID, task.Title, task.Priority)
}
```

Переменная `task` в этом цикле — копия текущей структуры. Её изменение не меняет элемент слайса:

```go
for _, task := range tasks {
	task.Completed = true
}

fmt.Println(tasks[0].Completed) // false
```

Чтобы изменить элемент слайса, обходите его по индексу:

```go
for index := range tasks {
	tasks[index].Completed = true
}

fmt.Println(tasks[0].Completed) // true
```

## Map задач по ID

Map может хранить `Task` как значение:

```go
tasksByID := map[int]Task{
	1: {
		ID:       1,
		Title:    "Купить молоко",
		Priority: 2,
	},
}
```

Такой map удобен для поиска задачи по ID:

```go
if task, exists := tasksByID[1]; exists {
	fmt.Println(task.Title)
}
```

Значение map нельзя изменить напрямую через поле:

```go
// tasksByID[1].Completed = true // ошибка компиляции
```

Сначала получите структуру в переменную, измените её и сохраните обратно:

```go
task := tasksByID[1]
task.Completed = true
tasksByID[1] = task
```

Это следствие того, что map возвращает копию значения. В будущей главе об указателях рассмотрим другой способ проектирования изменяемых моделей.

## Полная модель задачи

```go
package main

import "fmt"

type Task struct {
	ID        int
	Title     string
	Priority  int
	Completed bool
}

func main() {
	tasks := []Task{
		{
			ID:       1,
			Title:    "Купить молоко",
			Priority: 2,
		},
		{
			ID:       2,
			Title:    "Оплатить интернет",
			Priority: 3,
		},
	}

	tasks[0].Completed = true

	for _, task := range tasks {
		fmt.Printf("%d. %s | приоритет: %d | выполнена: %t\n",
			task.ID,
			task.Title,
			task.Priority,
			task.Completed,
		)
	}
}
```

## Частые ошибки

### Литерал без имён полей

```go
task := Task{1, "Купить молоко", 2, false}
```

Этот код компилируется, но хуже читается и зависит от порядка полей. Если порядок изменится, литерал придётся переписывать. Используйте имена:

```go
task := Task{
	ID:       1,
	Title:    "Купить молоко",
	Priority: 2,
}
```

### Изменение копии в `range`

```go
for _, task := range tasks {
	task.Completed = true
}
```

Изменяется копия. Нужен индекс: `tasks[index].Completed = true`.

### Прямое изменение поля структуры в map

```go
// tasksByID[1].Completed = true // ошибка
```

Получите значение, измените его и присвойте обратно в map.
