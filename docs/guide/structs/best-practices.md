# Лучшие практики: структуры

- Создавайте литералы структур с именами полей: это устойчиво к изменению порядка и проще читается.
- Группируйте в структуре данные одной сущности, например свойства одной задачи.
- Не используйте структуру как неограниченный контейнер: если поля относятся к разным обязанностям, выделите отдельную модель.
- Помните, что структура копируется при присваивании и передаче по значению.
- Изменяйте элементы `[]Task` по индексу, а не через переменную `range`, которая является копией.
- При хранении `Task` значением в map получите копию, измените её и присвойте обратно.

## Чек-лист

У модели есть ясная ответственность, её поля валидируются, а код осознанно различает копию структуры и исходное значение.
