# Рекомендации по коду: тестирование

- Тестируйте публичное поведение и бизнес-правила, а не случайные детали реализации.
- Называйте тесты по проверяемому сценарию: `TestTaskRename`, `TestStoreAddAndGet`.
- Для похожих случаев используйте table-driven tests и `t.Run` с понятными именами.
- Создавайте новое изменяемое состояние в каждом тесте или subtest.
- Проверяйте ошибку через `errors.Is`, если важна причина, а не текст сообщения.
- Делайте сообщения тестов диагностическими: показывайте фактический и ожидаемый результат.
- Запускайте `go test ./...` перед изменением или публикацией кода; конкурентные тесты — с `-race`.

## Чек-лист

Тест проверяет результат и побочный эффект, независим от порядка запуска других тестов, покрывает успешный, ошибочный и граничный сценарии.
