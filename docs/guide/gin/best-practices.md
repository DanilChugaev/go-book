# Рекомендации по коду: Gin

- Внедряйте Gin только в transport-слой; service, repository и модель не должны получать `*gin.Context`.
- Передавайте в нижние слои `c.Request.Context()`, а не новый `context.Background()`.
- Используйте `gin.New()` с явным набором middleware или `gin.Default()` — не подключайте оба набора logger/recovery одновременно.
- Сохраняйте стабильный JSON-контракт ошибок через отдельную структуру, а не случайные строки или технические `error`.
- Создавайте request DTO с разрешёнными полями; не принимайте из JSON серверные поля `id` и `completed`.
- Проверяйте JSON binding, значения после нормализации и известные ошибки service до выбора HTTP-статуса.
- Используйте request ID в response и структурированных логах, но не принимайте неконтролируемо длинные значения заголовка от клиента.
- Recovery должен логировать проблему на сервере и возвращать клиенту нейтральный `500`, а не текст panic.
- Тестируйте Gin router через `httptest` и fake service; не запускайте реальный порт в unit-тестах.

## Чек-лист

Gin заменяет только HTTP-обвязку, service и repository остаются независимыми от фреймворка, каждый запрос имеет request ID, panic не завершает сервер, а публичный HTTP-контракт закреплён тестами.
