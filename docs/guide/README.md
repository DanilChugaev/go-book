# Предисловие

Я начал этот учебник, чтобы упорядочить собственное изучение Go и собрать материал в том виде, в котором мне самому было бы удобно проходить язык: от коротких объяснений и запуска первых программ до создания настоящего backend-приложения.

Учебник построен не как энциклопедия языка, а как последовательность небольших шагов: сначала вы осваиваете синтаксис и модели данных, затем тесты и конкурентный код, после — HTTP API, PostgreSQL, Docker и доставку приложения.

Это не перевод официальной документации и не попытка заменить её. Я хочу сделать понятный русскоязычный маршрут для человека, который начинает с нуля и регулярно пишет код; первоисточники остаются обязательными для точных деталей и реального production-кода.

Сквозной проект — **Task Manager API**. Почти каждая тема получает прикладной контекст: задача, её валидация, хранение, экспорт, HTTP-обработчик, база данных или инфраструктура. В финале получается не набор несвязанных упражнений, а API, которое можно запустить локально, проверить, упаковать в контейнер и доставить в окружение.

## Для кого этот учебник

Учебник рассчитан прежде всего на новичка в Go и backend-разработке. Предыдущий опыт программирования не обязателен, но будут полезны базовые навыки работы с файлами, терминалом и редактором кода.

Он также подойдёт разработчикам из других языков, которые хотят пройти Go последовательно, а не только сравнить его синтаксис со знакомым стеком. Если вы уже пишете на Go, используйте содержание как карту тем, а задания и рекомендации по коду — как точки для самопроверки.

Для глав об инфраструктуре понадобятся Docker Desktop или Docker Engine с Docker Compose. Для финального production-сценария полезен GitHub-аккаунт и, при желании пройти деплой целиком, VPS. Эти инструменты появляются постепенно: в начале достаточно Go и терминала.

## К какому результату мы идём

Цель — не выучить набор конструкций наизусть, а научиться применять Go для backend-разработки. К концу основного маршрута вы сможете:

- создавать Go-модули, собирать и форматировать программы;
- работать с типами, строками, функциями, слайсами, map, структурами, методами, интерфейсами и ошибками;
- писать unit-тесты, работать с файлами и JSON, запускать `go vet` и race detector;
- понимать goroutine, каналы, `select`, mutex и `context`;
- проектировать слои handler → service → repository и не смешивать HTTP, бизнес-правила и инфраструктуру;
- создавать JSON API сначала на `net/http`, затем на Gin;
- вызывать внешние API через стандартный `http.Client` и Resty;
- настраивать env и `.env`, structured logging, request ID, graceful shutdown и health-check;
- хранить данные в PostgreSQL через `database/sql` и pgx, управлять схемой через Goose и проверять её в DBeaver;
- запускать API и PostgreSQL в Docker Compose, собирать multi-stage image;
- настраивать GitHub Actions, integration-тесты, публикацию image в GHCR, базовый deploy на VPS и rollback по SHA-версии.

Основной маршрут состоит из 35 глав. После него начинается отдельный **продвинутый блок**: углублённые ошибки и ресурсы, generics, конкурентные паттерны, performance и profiling. Он не обязателен для первого прохода: сначала завершите основной Task Manager API.

## Карта пути

Основной курс разбит на несколько частей:

1. **Основа языка** — первая программа, типы, строки, условия, циклы и функции.
2. **Данные и модели** — слайсы, map, структуры, методы, указатели, интерфейсы, ошибки и пакеты.
3. **Надёжность и ввод-вывод** — тесты, файлы, JSON, время и дедлайны.
4. **Конкурентность** — goroutine, каналы, `select`, mutex и `context`.
5. **Backend и production-подготовка** — логирование, `net/http`, Gin, HTTP-клиенты, configuration, Docker, PostgreSQL, CI/CD и итоговая интеграция.

Подробный порядок, ссылки и статус тем находятся в [содержании](content.md). Не перескакивайте сразу к Gin, Docker или PostgreSQL, если ещё не уверены в функциях, ошибках, `context` и тестах: поздние главы опираются на эти навыки.

## Как устроен урок

Каждая глава основного маршрута содержит:

- **цель урока** — измеримый результат после прохождения;
- **теорию** — только необходимое объяснение с небольшими исполняемыми примерами;
- **частые ошибки** — типичные неверные решения и их причины;
- **самопроверку** — короткий квиз по ключевым понятиям;
- **задания** — задачу, критерии готовности, подсказки и скрытые решения;
- **рекомендации по коду** — краткий checklist решений, которые стоит сохранить в проекте.

Кодовые фрагменты иллюстрируют конкретную главу, а полный проект вы собираете постепенно. Иногда пример намеренно проще финальной архитектуры: например, сначала API работает в памяти, а PostgreSQL появляется только после Docker и SQL-глав. Не переносите учебный фрагмент в production без понимания его ограничений.

## Как проходить учебник с пользой

1. Не ограничивайтесь чтением: набирайте примеры сами, запускайте `go run .` и меняйте входные данные.
2. Перед открытием решения попробуйте выполнить задание и свериться с критериями готовности.
3. После каждой главы запускайте рекомендованные проверки: минимум `gofmt`, `go test` и, где уместно, `go test -race`.
4. Используйте кнопку копирования у примера и [Go Playground](https://go.dev/play/) для небольших экспериментов. Для Task Manager API работайте локально в редакторе и Git-репозитории.
5. Не пропускайте тесты, ошибки и `context`: именно они связывают синтаксис Go с реальной backend-разработкой.
6. В инфраструктурных главах сначала проверяйте команды локально, затем переносите их в Docker и CI. Не добавляйте secrets, `.env` и production DSN в Git.
7. Если пример, термин или ошибка непонятны, вернитесь к предыдущей теме или к справочнику, а не пытайтесь запомнить объяснение без практики.

## Об официальной документации

Этот учебник объясняет путь и даёт практику, но окончательным источником поведения языка остаются официальные материалы Go:

- [документация и руководства](https://go.dev/doc/);
- [спецификация языка](https://go.dev/ref/spec);
- [стандартная библиотека](https://pkg.go.dev/std);
- [Effective Go](https://go.dev/doc/effective_go).

Для сторонних инструментов сверяйтесь и с их официальной документацией: Gin, Resty, PostgreSQL, pgx, Goose, Docker, GitHub Actions и DBeaver развиваются независимо от Go. Особенно важно проверять документацию при обновлении версии, настройке безопасности, производительности и production-инфраструктуры.

## Использование ИИ и проверка материалов

При подготовке учебника я использую ИИ как рабочий инструмент: он помогает составлять черновики, предлагать структуру уроков, формулировать объяснения, находить пробелы и готовить варианты упражнений. Это ускоряет работу, но не делает результат автоматически достоверным.

Поэтому для материала действует следующая политика:

- ИИ не является источником истины и не заменяет официальную документацию Go.
- Я редактирую сгенерированные фрагменты, проверяю утверждения и привожу терминологию к единому стилю.
- Новые или переработанные исполняемые примеры по возможности запускаются локально; документация и PWA-сборка также проверяются перед публикацией.
- Для спорных, зависящих от версии или низкоуровневых тем приоритет имеют официальная документация, спецификация и воспроизводимый код.
- В уже опубликованных главах могут оставаться ошибки, упрощения или устаревшие формулировки. Если вы заметили такую проблему, пожалуйста, сообщите о ней.

Примеры в учебнике предназначены для обучения. Перед использованием кода в рабочем сервисе его нужно самостоятельно проверить с учётом версии Go, нагрузки, безопасности, обработки ошибок, secrets, TLS, backup-стратегии и требований конкретной инфраструктуры.

- ссылку на страницу или её заголовок;

- фактический результат или текст ошибки;
- ожидаемый результат, если он очевиден.

Спасибо, что проходите этот путь вместе со мной. Начните с [содержания](content.md), затем перейдите к первой главе и первому запуску Go-программы.
