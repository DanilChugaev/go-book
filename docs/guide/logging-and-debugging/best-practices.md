# Рекомендации по коду: логирование и отладка

- Логируйте значимые события и ошибки на понятной границе обработки, а не на каждом уровне вызовов.
- Предпочитайте структурированные поля стабильным ключам: `task_id`, `path`, `duration`, `err`.
- Не записывайте в логи секреты, токены, пароли и лишние персональные данные.
- Передавайте `*slog.Logger` как зависимость и используйте `slog.Default()` как безопасный fallback.
- В unit-тестах направляйте логи в `io.Discard`, если проверка логов не является контрактом теста.
- Регулярно запускайте `go vet ./...`, `go test ./...` и `go test -race ./...`.
- Профилируйте только после измерения реальной проблемы и проверяйте эффект оптимизации повторным измерением.

## Чек-лист

Логи содержат достаточный контекст без чувствительных данных, ошибки не дублируются на всех уровнях, а диагностические инструменты входят в обычный workflow разработки.
