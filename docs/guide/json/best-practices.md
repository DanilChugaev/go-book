# Лучшие практики: JSON

- Используйте JSON-теги для стабильного внешнего API, а не полагайтесь на имена Go-полей.
- Модели для API и внутренние модели разделяйте, если их правила и поля начинают различаться.
- Проверяйте ошибку и у `Marshal`, и у `Unmarshal`.
- Не считайте успешный `Unmarshal` бизнес-валидацией: проверяйте допустимость полей отдельно.
- Для пустого списка выбирайте `[]T{}`, если API должен вернуть `[]`, а не `null`.
- Добавляйте контекст к ошибкам чтения файла, сериализации и десериализации отдельно.

## Чек-лист

Внешний JSON имеет предсказуемые имена полей, ошибки декодирования понятны, а загруженные данные проходят бизнес-валидацию до использования.
